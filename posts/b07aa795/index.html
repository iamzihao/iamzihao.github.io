Rust OS 入门：VGA 字符模式——往一块内存写字符，屏幕就有字了

Posted on 2026-09-07 Edited on 2026-09-10 Views: Word count in article: 3.8k Reading time ≈ 7 mins.

内核启动后，屏幕上出现了 Hello, World!——在还没有文件系统、设备驱动和 std 的情况下，这靠的是往一块特殊内存（0xB8000）里写字符，由 VGA 硬件读取并显示出来。这篇讲的就是这块内存和 VGA 的工作方式。

本文是《Writing an OS in Rust》（https://os.phil-opp.com/）入门系列的一篇，跟着你刚跑通的 cargo bootimage 往下走，解释教程里 println! 的第一站——VGA 文本模式。它正好用上《Rust OS 入门：物理地址 ≠ RAM 地址》里讲的 MMIO：0xB8000 就是读写内存 = 操作硬件最经典的实例。

📚 基本概念速读

名称 定义 省流
VGA 字符模式 早期文字版显示器，屏幕是字符格不是像素 80×25 的字符画布
显存（video memory） 显卡能读取的一块特殊内存 CPU 写它 = 显卡读它
0xB8000 VGA 文本模式显存起始地址 往这写，屏幕就变
属性字节（attribute） 描述字符颜色（前景+背景）的字节 每个字符配 1 字节颜色
字体表（font） VGA 内部字符编号→像素图案的查表 硬件级字符渲染器
MMIO 把设备寄存器/显存映射进地址空间 写内存 = 操作硬件
Framebuffer 现代显卡：CPU 直接控制每个像素 像素级画布

🖥️ VGA 字符模式是什么

先把它想象成一个非常早期的文字版显示器：屏幕不是由你直接控制每一个像素，而是被划分成一个个字符格子：

经典 VGA 文本模式是 80 列 × 25 行。也就是说，你不需要告诉显卡”把 (100, 50) 这个像素变成白色”，只需要告诉它：

“第 3 行第 10 列，显示字符 A，颜色白色。”

这就是字符模式（text mode）。

这正是我们在《物理地址 ≠ RAM 地址》里讲的 MMIO：0xB8000 不是普通 RAM，而是映射到 VGA 硬件的显存区域。写它不像写普通内存那样只是存数据，而是给显卡下达显示指令。

📐 整块显存有多大

80 × 25 = 2000 个字符，每个 2 字节 → 2000 × 2 = 4000 bytes ≈ 4 KB。整屏内容就这么多。

🖨️ 为什么操作系统刚启动时特别喜欢它

⚖️ VGA 字符模式 vs Framebuffer

VGA 字符模式 Framebuffer
你告诉显卡 “这里显示字符 A” “这个像素是 RGB(255,0,0)”
字体渲染 显卡查字体表帮你做 你自己写字体渲染逻辑
粒度 字符 像素

要画一个 A：字符模式写一个字节就完事；framebuffer 需要自己'A' → 字体库 → bitmap → 逐像素写入。

✅ 总结

VGA 字符模式 = 把一块特殊内存（0xB8000）当成屏幕上的字符表：CPU 往里面写字符 + 颜色，VGA 硬件按字体把字符转成像素显示出来。

对正在学 Rust OS 的你，VGA 的真正意义不是学会显示文字，而是第一次亲眼看到：

CPU 写内存 → 硬件观察这块内存 → 硬件产生可见输出。

这是理解 MMIO、设备驱动、framebuffer、硬件抽象 最好的入门例子——下一节开始，教程会把它封装成带 unsafe 隔离、能处理换行滚动的完整 VGA 模块，那就是把硬件操作包成安全抽象的第一课。
