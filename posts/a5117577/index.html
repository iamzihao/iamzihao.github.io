Rust OS 入门：物理地址 ≠ RAM 地址——地址空间、MMIO 与 Memory Map

Posted on 2026-09-02 Edited on 2026-09-06 Views: Word count in article: 4k Reading time ≈ 7 mins.

物理地址（Physical Address）是一张地址地图，RAM 只是地图上的一种东西。

本文是《Writing an OS in Rust》（https://os.phil-opp.com/）入门系列的第三篇，接上《Rust OS 入门：从按下电源键到内核接管》里”内存映射：Kernel 需要知道机器长什么样”那一节，把”物理地址空间里到底有什么、Bootloader 为什么要把 Memory Map 传给 Kernel”彻底讲透。

📚 基本概念速读

名称 定义 省流
物理内存（Physical Memory） 真正的 RAM 硬件 可读写的存储芯片
物理地址（Physical Address） CPU 访问物理资源时产生的地址 不一定是 RAM 的地址
物理地址空间（Physical Address Space） CPU 眼中全部地址的集合 一张地址地图，RAM 只是其中一种
MMIO（Memory-Mapped I/O） 把设备寄存器映射进地址空间 读写内存 = 操作硬件
Memory Map 记录地址区域用途的地图 Kernel 靠它分辨”能碰/不能碰”
Reserved 地址空间里存在但 OS 不能用的区域 千万别拿来当 RAM
虚拟地址（Virtual Address） 程序看到的地址，经 MMU 翻译 程序眼里的地址是”假的”

🔌 MMIO：内存映射 I/O

MMIO（Memory-Mapped I/O，内存映射 I/O） 的思想很简单：

把硬件设备的寄存器映射到物理地址空间里。

硬件工程师的思路是：CPU 本来就有”读地址 / 写地址”的机制，那干脆把设备寄存器也放进地址空间，CPU 就不需要额外的指令来访问设备了。

假设显卡把某个寄存器规定在物理地址 0xF0000000：

经典的例子是传统 PC 的显存区域：CPU 往物理地址 0xA0000 附近写数据，就会影响屏幕显示内容。现代 PCIe 设备也大量使用 MMIO，只是地址和机制更复杂。

⚠️ Reserved：为什么不能碰

某些物理地址区域存在于地址空间里，但操作系统不能随便使用。原因可能是：

  • 被硬件使用
  • 被固件使用
  • 对应 MMIO
  • 有特殊用途
  • 芯片组保留区域

再回到开头的疑问：“16GB RAM 里面有什么？”要分两种情况回答：

  • 问 RAM 这块硬件运行时存什么：Kernel、Kernel Stack/Heap、Page Tables、各进程的 Code/Data/Heap/Stack、文件缓存、网络缓冲区、设备缓冲区等。
  • 问 CPU 的整个物理地址空间里有什么：可用 RAM、Reserved 区域、Firmware/ROM、MMIO、ACPI 硬件信息、APIC 控制区域等。

这两个”内存里有什么”不是一回事。

✅ 总结

物理地址是 CPU 用来定位物理资源的地址，RAM 只是地址空间里的一种资源。 Kernel 靠 Bootloader 传的 Memory Map 分辨”能碰 / 不能碰 / 是硬件”，才能安全地建立 Frame Allocator，进而进入虚拟内存的世界。

下一步建议沿着 Memory Map → Frame Allocator → Page Table → Virtual Address 继续：搞清”一个 4 KiB 的物理页帧到底是什么，Page Table 怎么把虚拟地址翻译成物理地址”，前面的所有概念就会真正串起来。
