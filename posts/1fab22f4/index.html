PCIeMonitor 精读：把规则匹配搬进 PCIe 链路，在硬件上查挖矿

Posted on 2026-10-15 Edited on 2026-10-11 Views: Word count in article: 3.7k Reading time ≈ 7 mins.

概括成一段话：监测点不放主机、不放 GPU，而是直接坐落在 PCIe 链路上——把主机发往 GPU 的指令流顺手复制一份，用一个硬件版的多模式匹配引擎逐条扫过，命中了挖矿程序的指令特征就报警。因为整套逻辑跑在 FPGA 里，它对被监测的程序零运行时开销，而且只为了这件事花掉 2.3 瓦。

论文：PCIe Monitoring for Secure Code Execution in Heterogeneous System Architectures（2025 IEEE International Conference on Cyber Security and Resilience, CSR）

作者：Iasonas Georgakas、Eva Papadogiannaki、Konstantinos Georgopoulos、Sotiris Ioannidis（Technical University of Crete）

前面几篇讲的都是同一件事的两面：如何在 PCIe 链路上把数据拿走。这篇换了个立场——如果这条链路真的能被随意读写，那么反过来，它也是一个绝佳的检测点。想看清一台机器上到底在跑什么，链路本身就是一个天然的观测位。

📚 基本概念速读

名称 定义 记忆点
Endpoint PCIe 链路里设备侧的那一端 本文用一块 FPGA 板扮演 GPU
XDMA Xilinx 的 DMA IP 核，负责 PCIe 上的数据搬运 用来把主机发来的数据接进来
IP core FPGA 里可复用的硬件功能模块 本文的监测引擎就是若干个 IP 核
Aho-Corasick 多模式匹配算法：一次扫描就能同时找出一组关键词 杀毒软件和 IDS 的常用引擎，本文把它搬到硬件上
MPSoC 自带处理器核的 FPGA SoC 本文用 ZCU102 当主机
BRAM FPGA 内部的块状存储 GPU 仿真就是一块 BRAM
YARA / SNORT 两个常见的规则匹配工具 论文拿它们所在的生态当作对比基线
TEE（可信执行环境） 靠隔离来保证执行安全的硬件机制 论文点出它的代价：会引入额外开销

🎬 起点：一个很实际的运维问题

论文的开场不是学术动机，而是一类真实事故：有人在你不知情的情况下，拿你的 GPU 挖矿。

微软和思科都报告过这类事件。GPU 被挖矿程序占满，租户的关键任务跑不动，可用性直接受损。而论文对现有手段的评价相当直接：

  • 软件工具：可以查，但随时可能被恶意用户绕过或关掉；
  • TEE：把代码隔离起来执行，安全性有了，但会给系统加上额外开销；
  • 商用 PCIe 分析仪：能看链路，但很贵。

于是论文提了一个折中的思路：不改变主机、也不改变 GPU，只是在链路上放一个硬件监测器。主机把 GPU 指令发下去的时候，监测器顺手复制一份扫一遍，命中已知的恶意指令模式就报警——形态上就是一个基于规则的入侵检测系统（IDS），只不过规则匹配的是 GPU 指令。

🧱 怎么搭：两块 FPGA 板演一台机器

因为要在链路上插东西，实验平台得同时造出主机侧和设备侧。论文用了两块板：

  • 主机侧：AMD/Xilinx 的 ZCU102，上面有 4 个 ARM A35 核，跑用 Petalinux 做的嵌入式 Linux，装上 Xilinx 的 PCIe 驱动，负责把指令数据发向 PCIe；
  • 设备侧：AMD/Xilinx 的 KC705，扮演一块 GPU，同时把监测器一起装在里面。

设备侧这块板的内部结构是整篇文章的核心：

注意第三行那句话——监测器不是拦在中间做检查，而是旁路：PCIe 流量同时送往匹配引擎和 GPU 仿真两侧，谁也不挡谁。这也是它敢说零开销的底气：被监测的程序根本不知道旁边有人在看。

🔍 监测引擎：把 Aho-Corasick 改成认 GPU 指令

选 Aho-Corasick 的理由很直接。常规的逐个规则去扫，扫 N 条规则就要过 N 遍数据；而 Aho-Corasick 把所有模式编成一棵树，一趟扫描就能同时匹配全部模式。它正是 SNORT 这类 IDS 的底座。

论文做的主要改造是换输入类型：原版 Aho-Corasick 处理的是字符流，这里要处理的是 GPU 指令流。为此他们把每个 IP 核做成两级流水线，每级内部再拆成两个子级，用一个有限状态机沿着预存的状态树走，每进来一条指令就往前推进一格。走完之后输出一个分数，表示匹配上了多少条恶意模式。

有一个工程细节值得记下：IP 核可以按 PCIe 流通道数复制多份并行跑。论文测的就是 1 份和 2 份两种情况——这个数字在后面会决定它到底比 CPU 快还是慢。

🎯 规则从哪来：从真实的挖矿程序里挖指令模式

监测器需要规则，而这篇论文的规则不是手写的，是挖出来的。

流程是这样的：先用 NVIDIA 的 cuobjdump 从真实的 GPU 程序里导出汇编，再转成十六进制，最后只保留操作码（opcode）——也就是把指令序列抽出来，把操作数全丢掉。候选的挖矿程序包括 xmrMiner、yadaGPUminer、一个简单的 CUDA 比特币矿工和 Blake2s 矿工；对照组则从排序、哈希表、遗传算法等常规程序里选，以保证两边有足够差异。

对比之后浮出来一个信号：SHF 和 LOP 这两类指令在普通程序里约占 20%，在挖矿程序里占到 40%。于是论文用 SPMF 框架配合 BIDE+ 算法去挖频繁闭合序列模式，窗口大小定成 7 条指令——这个数字不是随便选的，Kepler 架构的 GPU 每 7 条指令后面会跟一个控制码。

挖出来的模式都是 SHF 与 LOP 的排列组合：

模式 含义
SHF → SHF → LOP 连续三条里两条移位、一条逻辑运算
LOP → LOP → LOP → LOP 连续四条逻辑运算
SHF → LOP → SHF 移位与逻辑运算交替

论文把它们当规则用，逐条确认了各个挖矿程序命中哪些、常规程序又是否误报。

📊 代价：快 1.55 倍，省 543 倍电

评估平台是 Intel 第 13 代 i5（4.3 GHz）对 KC705（100 MHz），基线是在 CPU 上跑同一个 Aho-Corasick 算法（也就是 SNORT 那一套）。

指标 结果
执行时间 / 处理吞吐 FPGA 用 2 个 AC 核时是 CPU 的 1.55×
能耗 同等输入下，2 个 AC 核的 FPGA 比 CPU 少 543×；1 个核时少 275×
功耗 FPGA 2.267 W（1 核）／2.294 W（2 核）；CPU 约 30 W
对被监测程序的开销 零（纯硬件旁路，不参与主机与设备的执行路径）

这里有一个论文自己写得很坦白的细节，值得单独拎出来：只放 1 个 AC 核的时候，FPGA 在延迟和吞吐上都不如 CPU。加上第 2 个核并行跑之后才反超——因为并行把计算时间砍了一半。而功耗几乎没变（2.267 W 到 2.294 W），多出来的那点差异全在动态功耗里。

这也解释了它为什么能同时赢两头：功耗的差距来自平台本身（不是 FPGA 效率高，而是 CPU 这个平台本身耗电 30 瓦），而性能的差距靠并行度补上。

⚠️ 这篇的边界

位置 要注意的地方
对比基线的口径 1.55× 与 543× 都是拿 CPU 上跑同一个 Aho-Corasick 算法来比的，不是端到端系统开销，也不是和商用 PCIe 分析仪比
这是仿真平台 主机是 ZCU102 板子，GPU 是 KC705 上的一块 BRAM——只用来存 GPU 二进制代码，并不真的执行。论文自己把这一点列为未来工作
监测的是指令内容，不是 TLP 它靠的是 GPU 指令流的内容匹配，不做通用的 TLP 解析（不看去哪个地址、也不看包类型）。这一点和解析包头做流量画像是两套完全不同的路子
规则是静态的 状态表在部署时就烧进去了，运行中改规则是论文的未来工作（要靠增加流通道去部分重配置）。而且规则集只覆盖挖矿这一类，论文也把它列为可以继续扩展的方向
发表场所 这是 IEEE CSR（Cyber Security and Resilience）的会议论文，不是安全四大，定位更偏向工程原型与可行性验证

论文列的未来工作里，有一条和链路监测这件事的走向关系最大：用一块 PCIe interposer（转接板）加上可编程逻辑，插进真实的 CPU 与 GPU 之间，把监测器嵌进去。从两块 FPGA 板互相演，到插进真机，差的正是这一步——而这步也是所有链路侧工作的共同门槛。

✅ 总结

在 PCIe 链路上做旁路监测，是防御方对同一条链路的正当用法：把主机发往 GPU 的指令流复制一份，交给一个硬件版的多模式匹配引擎，就能在不影响被监测程序的前提下、以极低的能耗查出挖矿程序。

三个可以带走的要点：

  1. 观测点搬到了链路上，代价是几瓦。整套监测是旁路的，被监测的程序零开销、也感知不到；换成在主机上跑同样的匹配算法，功耗要高两个数量级；
  2. Aho-Corasick 这类老算法在硬件上依然好用，关键改动只有一处——把输入从字符流换成 GPU 指令流；
  3. 它的局限和优势来自同一处：因为只看指令内容、不做通用解析，规则集就是它的能力上限；反过来，规则挖得好不好（SHF 与 LOP 在挖矿程序里占比翻倍）直接决定了这套监测有没有用。

再把视线拉远一点：同一条 PCIe 链路，攻击方可以用它偷模型，防御方也可以用它查异常。两边用的都是在链路中间插一个东西、把流量复制一份这同一个动作，差别只在拿走之后拿去做什么。
