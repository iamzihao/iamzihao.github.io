Rust OS 前置：借用与生命周期——引用、裸指针与 unsafe

Posted on 2026-09-07 Views: Word count in article: 2.5k Reading time ≈ 5 mins.

Rust 与 C 的分水岭在”内存归谁管”：C 靠程序员自觉，Rust 用一套编译期规则保证安全。这套规则的核心就是所有权、借用（& / &mut）与生命周期，而 OS 开发还要在此基础上接触裸指针与 unsafe。这篇把这条主线一次讲清。

接上一篇《Rust OS 前置：从 C 到 Rust》。建议先记住一句主线：对象 → 所有权 → 引用 → 借用 → &mut → 裸指针 → unsafe → 生命周期。

📚 基本概念速读

名称 含义 省流
&T 不可变引用（借用） 借用但不拿走
&mut T 可变引用 借来并允许修改
*T 解引用 访问指向的东西
*const T / *mut T 裸指针 “一个地址”
unsafe 绕过无法自动证明的操作 自己负责安全
as 类型转换 整数 → 裸指针
'static 生命周期：持续到程序结束 硬件映射内存常用
'a 生命周期名字 引用有效的区间

📌 裸指针 *mut T：只是一个地址

这里的 *mut Buffer 不是 &mut Buffer，而是裸指针：把 0xb8000 这个整数地址”解释成指向 Buffer 的地址”。粗略对应 C 的 Buffer *buffer;。

⚖️ &mut T 和 *mut T 一定要分清

Rust 含义 粗略 C 对应
T 一个对象 T
&T 不可变引用 T *
&mut T 可变引用（受借用规则约束） T *
*const T 裸指针（只读） const T *
*mut T 裸指针（可写） T *

最简理解：

区别在于：&mut T 受借用检查器约束（同一时刻只能有一个），而 *mut T 是裸地址，编译器不替你保证什么——所以使用裸指针通常需要 unsafe。

⚠️ unsafe：你承担安全责任

为什么需要 unsafe？因为 Rust 无法证明 0xb8000 处真的有一个合法的 Buffer——地址是硬件规定的，编译器看不到。unsafe 是说：

“这个操作我知道是安全的，由我负责。”

但 unsafe 不是”进入 C 模式”，不是说 Rust 规则全部关闭：

在 unsafe 块里取得的 &mut Buffer，拿出来的仍然是一个正常引用，之后继续受类型系统与借用检查约束。这正是把”危险的硬件访问”封装在安全抽象里的基础：内部小范围 unsafe，外部暴露安全接口。

后面还会看到 'a、'b 这类生命周期名字：

'a 只是给某段”引用有效区间”起的名字：&'a T 是”生命周期为 'a 的 T 的引用”。编译器靠这些名字检查：返回的引用不会比它借的东西活得更久（防止悬垂引用）。'static 是其中最长的一个特例。

✅ 总结

借用与生命周期的主线是：& 借而不取 → &mut 借来修改 → * 解引用 → 裸指针 *mut T 只是地址 → 访问裸指针要 unsafe 且自己负责 → 生命周期（'static / 'a）描述引用能活多久。
