Rust OS 前置：逐行拆解 VGA 的 Writer

Posted on 2026-09-07 Edited on 2026-09-10 Views: Word count in article: 10k Reading time ≈ 18 mins.

前三篇的语法与思想，最终都落在一个真实的模块上：VGA 文本模式的 vga_buffer.rs。这篇不贴全文，而是把它拆成九块来读——从颜色怎么压进一个字节，一直讲到 println! 怎么变成对显存的一次写。

前置阅读：《从 C 到 Rust》《借用与生命周期》《属性与内存布局》，以及《Rust OS 入门：VGA 字符模式》。

📚 素材速读

要拆的部件和它们所属的层：

部件 职责 对应层
Color / ColorCode 16 色编号，以及把前景与背景压进一个字节 第一层
ScreenChar 一个屏幕格子：字符 + 颜色 第二层
Buffer 25 × 80 个格子，映射到 0xb8000 第二层
Writer 记录当前写到哪一列、用什么颜色，对外提供写屏接口 第三层
write_byte / new_line / clear_row 写一个字符、屏幕上滚一行、清空一行 第四、五层
write_string 把 &str 拆成字节逐个写出 第六层
fmt::Write 让 Writer 接进 Rust 的格式化体系 第七层
WRITER 全局唯一的 Mutex<Writer> 第八层
print! / println! 提供给内核其余部分使用的打印宏 第九层

从第七层起会碰到三样前面没讲过的语法：trait（接口）、泛型与锁、宏。每一层都先把它们解释清楚，再读代码。

🎨 第一层：Color 与 ColorCode——颜色怎么压进一个字节

#[repr(u8)] 是这里的枢纽：没有它，枚举的底层类型不由你决定，Color::Yellow as u8 拿到的值也不可控。ColorCode 那层包装解决另一个问题——给一个字节起个有语义的名字，同时靠 #[repr(transparent)] 保证它真的还只是一个字节，能直接塞进下一层的 struct 里。

🧱 第二层：ScreenChar 与 Buffer——一个格子与整块屏幕

Volatile 是这一层唯一需要展开的地方。显存是内存映射 I/O（MMIO），它的内容会被硬件改动，而编译器看不到这件事；没有这层包装，编译器可能把连续的多次写合并掉，也可能认为刚写进去的值还在寄存器里、读取时不必回内存。第五层的 new_line 要整行读出来再写回去，正是这种读写都必须真的落在内存上的场景。Volatile<T> 自身也是 #[repr(transparent)] 包装，所以 Buffer 在内存里仍然严格是 25 × 80 × 2 字节，和显存逐格对应。

🖋️ 第三层：Writer——写字的人

三个字段凑起来就是一句话：光标在哪、用什么颜色、往哪写。后面所有方法都只是围绕这三件事操作。

✍️ 第四层：write_byte——往显存写一个字符

&mut self 是必需的：写一个字符要同时改 column_position 和显存内容，属于可变借用（篇二）。另外留意 row 固定取最后一行——这一版实现里光标不高亮也不移动，始终停在末行，写满一行就把整屏上滚，这也是第五层存在的理由。

📜 第五层：new_line 与 clear_row——屏幕滚动

这段的语义是 把显存里的内容搬到显存里的另一个位置，所以它必须用 volatile 读写：只要中间某次读被缓存进寄存器，搬过去的就可能是旧值。另外这两个方法都没有 pub，滚动和清行是内部细节，只由 write_byte 调用（篇一：pub、私有）。

🔤 第六层：write_string——从字符串到字节

0x20..=0x7e 是可打印 ASCII（空格到 ~），加上换行符，这两类原样写屏；其余字节统一写成 0xfe，而它在 VGA 字体里是实心方块。中文每个字 3 个字节且都大于 0x7e，所以走的是这一路——屏幕上一串方块字的来历，也是这套 VGA 打印只适合英文的原因。

🖨️ 第七层：fmt::Write——把 Writer 接进格式化协议

前六层已经攒出一套能用的写屏能力，但只能这么调用：writer.write_string("Hello")。想要 println!("x = {}", x) 这种带占位符的写法，就得走 Rust 的格式化机制——{} 怎么变成最终文本、参数怎么拼进去，由 core::fmt 里的一套协议负责。这一层做的事，就是让 Writer 加入这套协议。

  • impl fmt::Write for Writer 是一句声明：Writer 实现 fmt::Write，下面就得把必选方法补齐。
  • write_str 就是那个必选方法，&mut self 因为要写显存（篇二）。
  • fmt::Result 是 Result<(), fmt::Error> 的别名；Ok(()) 表示写成功了。这里恒为成功，因为往显存写字不会失败。
  • 实现完之后，Writer 自动获得 write_fmt——它由默认实现提供，负责把 {}、{:?} 这些占位符格式化好，再一段段调用我们写的 write_str。所以不用自己解析格式串。
  • core::fmt 而不是 std::fmt：内核是 #![no_std]，只有 core（《VGA 字符模式》里提过）。另外 use core::fmt; 写在文件中部——Rust 的 use 可以出现在模块里的任何位置，作用范围都是整个模块。

🌍 第八层：lazy_static 与 Mutex——造一个全局 Writer

前面所有方法都要 &mut self，所以得先有 Writer 实例。屏幕只有一块，这个 Writer 也就应该只有一个，而且内核各处都要能拿到——结论是把它做成全局变量。这一层解决的就是怎么造出这个全局变量。

先把这层出场的三个新东西说清楚：

  • static 是 Rust 的全局变量，但有个硬要求：初值必须在编译期就能算出来。
  • Mutex<T> 是泛型，读作 一把锁，里面装着一个 T。Mutex<Writer> 就是 装着 Writer 的锁：谁要访问里面的值，先拿锁，同一时刻只有一个持有者。
  • lazy_static! 是宏。宏和函数接收的东西不同：函数收值，宏收代码片段，并在编译期把它展开成别的代码。

这段看起来像 static 声明，其实整块都是 lazy_static! 的输入：它在编译期生成一个真正的全局变量，并把构造 Writer 这件事推迟到第一次访问 WRITER 时执行。三处设计都值得追问一句：

  • 为什么不直接写 static WRITER: Writer = ...：两个障碍。一是初值必须是编译期常量，而这里要把整数地址转成指针再解引用，编译期算不出来；二是 Writer 里带着 &'static mut Buffer，可变的全局变量立刻会踩到别名规则（篇二）。
  • 为什么要套 Mutex：&'static mut 不允许出现第二个引用。自旋锁把对 Writer 的访问串成一条线，同一时刻只有一个持有者，也就不会同时存在两个 &mut。用 spin::Mutex 而不是 std::sync::Mutex，是因为后者要靠系统调用，而内核里还没有系统调用可用。
  • pub static ref 里的 ref 是什么：它不是 Rust 关键字，而是 lazy_static! 自己的语法，意思是 WRITER 这个名字背后是一个引用，指向下面那个值——构造被推迟了，所以拿到的不能是值本身。

（顺带一提，lazy_static 在 Cargo.toml 里开了 spin_no_std feature：惰性初始化本身也要一把锁来保证只初始化一次，而裸机环境没有 std 的 Once，所以让它改用 spin。）

组合起来，unsafe { &mut *(0xb8000 as *mut Buffer) } 的意思是：

通过裸指针找到那块显存，把它借成一个可修改的 Rust 引用，交给 Writer 使用。

套 unsafe 是因为编译器无法证明 0xb8000 处真的有一个合法的 Buffer——这是硬件规定的事实，由程序员负责声明。unsafe 只把这道门打开一条缝：&mut 拿到手之后，后续操作仍受类型系统与借用检查约束（篇二）。同一个 unsafe 块还隐含另一个承诺：这块显存只会经由这一个引用访问，不会同时造出别名——这正是它被放进 Mutex 的原因。另外，这个地址能直接解引用，是因为此时 bootloader 已经做好分页映射，让这个虚拟地址正对着物理显存。

🔗 第九层：print! 与 println!——宏与 _print

WRITER 有了，但每次打印都写 WRITER.lock().write_fmt(format_args!(...)) 太啰嗦；而且想写出 println!("x = {}", x) 这种形式，参数个数必须能变——函数做不到：函数签名里的参数个数是固定的，{} 后面跟几个参数得由调用方现场决定。这正是宏的用武之地。

逐点看：

  • macro_rules! print { ... } 定义了一个名叫 print 的宏，#[macro_export] 让它导出，别的模块或 crate 也能用。
  • $($arg:tt)* 是宏的参数表，拆开读：$arg 是一个捕获变量，tt 表示一个 token tree（一个词，或一对括号括起来的整体），$( ... )* 表示重复零次或多次。合起来就是 捕获任意多个 token——所以 println!()、println!("a")、println!("{} {}", a, b) 都落在这条规则里。
  • => 右边是展开结果：把捕获到的片段原样塞进 format_args!。这是编译器内置宏，它就地整理出一份 fmt::Arguments（格式串 + 各参数的引用），全程不分配内存，适合 no_std 内核。
  • $crate 是 定义这个宏的那个 crate 的占位符。宏导出后可能在别的 crate 里展开，那时写死 crate::vga_buffer::_print 会解析到调用方去，用 $crate 才能保证路径指回这里。
  • println! 有两条规则：无参数时展开成 print!("\n")，有参数时补一个换行再转交 print!。宏规则自上而下匹配，两条不会打架。
  • _print 是普通函数，负责收尾：#[doc(hidden)] 只表示它不进文档，但仍必须是 pub——宏在别处展开时得能调到它。函数体第一行 use core::fmt::Write; 是把 trait 带进作用域，因为 write_fmt 是 trait 方法（第七层）；WRITER.lock() 拿到锁的守卫 MutexGuard，write_fmt 拆出的一段段文本最终落到 write_str；unwrap() 不会 panic，因为 write_str 恒返回 Ok。

🧅 学习方法：Rust 代码可以剥洋葱

看到类似的表达式不要当成一整坨语法，而是从右往左一层层拆：

Rust 代码几乎都可以这样拆开读。学 Rust OS 时，最值得先打通的主线就一条：

对象 → 所有权 → 引用 → 借用 → &mut → 裸指针 → unsafe → 生命周期

这条线弄明白后，后面 Writer、Volatile、lazy_static!、spin::Mutex、中断处理这些模块，基本都围绕同一套思想展开——只是包装越来越厚。这篇文章从第一层拆到第九层也是同一个道理：每一层单独看都不难，难的是把它们串成一条从 println! 到显存的通路。

✅ 总结

VGA 的 Writer 把前三篇的语法串成了一条完整链路：repr(u8) 的 Color 与 newtype ColorCode 把颜色压进一个字节 → repr(C) 的 ScreenChar 描述一个格子 → Volatile 包装的 Buffer 描述整块显存 → 整数地址经 as 变裸指针 → unsafe 加解引用变成 &'static mut 引用 → spin::Mutex 与 lazy_static! 把它变成全局唯一实例 → fmt::Write、print!、println! 一层层包装成安全接口。读这类代码的关键是剥洋葱：一层层拆开看每一步做了什么。

Happy Hacking! 🎉
